# Support

## Self-Hosted and open-source support

Community support is best effort. Use a GitHub issue for a reproducible defect, documentation gap, or narrowly scoped feature proposal. Search for an existing issue first and include the RefKit version or source revision, deployment mode, relevant redacted logs, expected behavior, and actual behavior.

Do not post secrets, environment files, access tokens, customer data, private URLs, or production database contents. Use the process in [SECURITY.md](./SECURITY.md) for suspected vulnerabilities.

Self-Hosted operators are responsible for deployment, upgrades, backups, recovery, host security, database operations, email deliverability, storage, DNS, reverse proxy, and TLS. The community project does not provide a service-level agreement, emergency operations, or guaranteed response time.

## RefKit Cloud

RefKit Cloud support is an operated service with separate terms and scope. Cloud account and billing questions can be sent to `support@refkit.net`. Cloud support does not extend to operating a third-party Self-Hosted deployment.

## Publication gate

Before public launch, maintainers must enable the selected GitHub issue channels, verify moderation access, and confirm that linked support and security contacts work. This file does not claim those external settings are already active.
